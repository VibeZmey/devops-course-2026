# Конфигурация виртуальной машины devops-vm

## 1. Параметры машины

| Параметр | Значение |
|---|---|
| Средство виртуализации | VirtualBox 7.x |
| Гостевая ОС | Ubuntu Server 24.04 LTS, 64-bit |
| Имя узла | `devops-vm` |
| Полное доменное имя (FQDN) | `devops-vm.devops.local` |
| Объём оперативной памяти | 2048 МБ |
| Количество ядер процессора | 2 |
| Объём дискового накопителя | 25 ГБ, динамически расширяемый |
| Тип установки | Ubuntu Server, без minimized-набора |
| Компонент OpenSSH server | установлен |

## 2. Сетевые интерфейсы

| Адаптер | Тип адаптера | Полученный адрес | Назначение |
|---|---|---|---|
| Адаптер 1 | NAT | `10.0.2.15/24`, шлюз `10.0.2.2`, DNS `10.0.2.3` | Доступ в Интернет, установка пакетов, проброс SSH с хостовой системы |
| Адаптер 2 | Виртуальный адаптер хоста (Host-only) | `192.168.56.101/24`, сеть `192.168.56.0/24` | Доступ с хостовой системы, локальное имя `devops.local`, дальнейшее использование для Nginx в практической работе № 6 |

Примечание. Фактический адрес Host-only уточняется командой `ip -brief address`. В работе использован адрес `192.168.56.101`.

Локальное разрешение имён:

- на хостовой системе в файл `hosts` добавлена запись:
  ```text
  192.168.56.101 devops.local
  ```
- на сервере задано:
  ```text
  hostnamectl set-hostname devops-vm
  ```
- в `/etc/hosts` сервера присутствует строка:
  ```text
  127.0.1.1 devops-vm.devops.local devops-vm
  ```

## 3. Правило проброса портов

Проброс выполнен для сетевого адаптера 1 типа NAT.

| Этап | Порт хостовой системы | Порт гостевой системы | Протокол | Назначение |
|---|---:|---:|---|---|
| До усиления SSH | 2222 | 22 | TCP | Первичное подключение к SSH после установки ОС |
| После задания 2 | 2222 | 2222 | TCP | Подключение к SSH после изменения порта службы |

Итоговая конфигурация после выполнения работы: **хост `127.0.0.1:2222` → гость `devops-vm:2222/tcp`**.

## 4. Учётные записи

| Имя | Принадлежность к группам | Способ аутентификации |
|---|---|---|
| `student` | `student`, `sudo` | Пароль; используется для консольного входа и выполнения `sudo`. После включения `AllowUsers devops` SSH-доступ для `student` запрещён |
| `devops` | `devops`, `sudo` | SSH-аутентификация по ключу Ed25519; парольная аутентификация по SSH отключена; `sudo` — по паролю |
| `root` | `root` | SSH-вход запрещён директивой `PermitRootLogin no`; прямой вход не используется |

Ключевой материал:

- на хостовой системе создана отдельная ключевая пара:
  ```text
  ~/.ssh/devops_vm
  ~/.ssh/devops_vm.pub
  ```
- открытый ключ размещён на сервере в файле:
  ```text
  /home/devops/.ssh/authorized_keys
  ```
- права доступа:
  ```text
  ~/.ssh                 700
  ~/.ssh/authorized_keys 600
  ```

На хостовой системе используется файл `~/.ssh/config`:

```text
Host devops
    HostName 127.0.0.1
    Port 2222
    User devops
    IdentityFile ~/.ssh/devops_vm
    IdentitiesOnly yes
```

## 5. Служба SSH

| Параметр | Значение |
|---|---|
| Порт SSH | `2222` |
| Фактический прослушиваемый адрес | `0.0.0.0:2222` |
| Основной файл конфигурации | `/etc/ssh/sshd_config` |
| Дополняющий файл конфигурации | `/etc/ssh/sshd_config.d/99-hardening.conf` |
| Резервная копия основного файла | `/etc/ssh/sshd_config.backup` |
| Активация службы | `ssh.socket` отключён, используется `ssh.service` |

Изменённые директивы в `/etc/ssh/sshd_config.d/99-hardening.conf`:

| Директива | Значение |
|---|---|
| `Port` | `2222` |
| `PermitRootLogin` | `no` |
| `PasswordAuthentication` | `no` |
| `PubkeyAuthentication` | `yes` |
| `PermitEmptyPasswords` | `no` |
| `MaxAuthTries` | `3` |
| `LoginGraceTime` | `30` |
| `AllowUsers` | `devops` |
| `X11Forwarding` | `no` |
| `ClientAliveInterval` | `300` |
| `ClientAliveCountMax` | `2` |

Примечание. В Ubuntu 24.04 в каталоге `/etc/ssh/sshd_config.d/` может присутствовать файл `50-cloud-init.conf` с директивой `PasswordAuthentication yes`. Так как файлы читаются в лексикографическом порядке и действует первое встреченное значение, конфликтующую строку необходимо закомментировать. Проверка:

```bash
grep -r "PasswordAuthentication" /etc/ssh/sshd_config.d/ /etc/ssh/sshd_config
```

Проверка действующей конфигурации:

```bash
sudo sshd -t
sudo sshd -T | grep -Ei "^(port|permitrootlogin|passwordauthentication|maxauthtries|allowusers)"
sudo ss -tlnp | grep sshd
```

Ожидаемый результат: `sshd` слушает порт `2222`.

## 6. Правила межсетевого экрана

Используется UFW.

| Параметр | Значение |
|---|---|
| Состояние | `active` |
| Политика по умолчанию для входящего трафика | `deny` |
| Политика по умолчанию для исходящего трафика | `allow` |
| Политика для маршрутизируемого трафика | `disabled` / пересылка не используется |
| Регистрация событий | `medium` |

Перечень правил:

| № | Правило | Назначение |
|---|---|---|
| 1 | `80/tcp ALLOW IN` | HTTP, подготовка к практической работе № 6 |
| 2 | `443/tcp ALLOW IN` | HTTPS, подготовка к практической работе № 6 |
| 3 | `2222/tcp LIMIT IN` с комментарием `SSH rate-limited` | SSH с ограничением частоты подключений |
| 4 | IPv6-эквиваленты правил для `80/tcp`, `443/tcp`, `2222/tcp` | Доступ по IPv6 |

Примечание. Правило `ufw allow ssh` не используется, так как оно открывает порт `22` по файлу `/etc/services`, а не порт `2222`. Правило `limit` блокирует источник, инициировавший шесть и более соединений в течение 30 секунд.

Проверка:

```bash
sudo ufw status verbose
sudo ufw status numbered
```

## 7. Снимки состояния

| Наименование | Момент создания |
|---|---|
| `01-clean-install` | После установки Ubuntu Server, обновления системы и проверки сети, до выполнения аудиторной части |
| `02-keys-configured` | После создания учётной записи `devops`, настройки ключевой аутентификации и файла `~/.ssh/config` на хостовой системе |
| `03-ssh-hardened` | После усиления защиты SSH, проверки нового подключения и подтверждения работы службы на порту `2222` |

## 8. Веб-сервер

| Параметр | Значение |
|---|---|
| Устанавливаемый пакет | `nginx` (версия 1.24.0) |
| Путь к конфигурации ресурса | `/etc/nginx/sites-available/devops-site` |
| Каталог ресурса | `/var/www/devops-site` |
| Владелец каталога ресурса | `devops:devops` |
| Права каталога и файлов | `755` для каталогов, `644` для файлов |
| Путь к сертификату | `/etc/ssl/certs/devops.crt` (права `644`, владелец `root`) |
| Путь к закрытому ключу | `/etc/ssl/private/devops.key` (права `600`, владелец `root`) |
| Команда формирования сертификата | `sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout /etc/ssl/private/devops.key -out /etc/ssl/certs/devops.crt -subj "/CN=devops.local" -addext "subjectAltName=DNS:devops.local"` |
| Срок действия сертификата | 365 дней (1 год) |
